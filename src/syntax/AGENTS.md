# syntax

Tea frontend: source text → AST. `Source` (character cursor) → `Scanner` (incremental tokenizer) → `Parser` (recursive descent) → `File` (`nodes.ts`).

## Invariants

- The scanner is incremental: `next()` advances exactly one token by mutating the scanner's public fields (`tok`/`pos`/`lit`/`kind`/`op`/`prec`), valid only until the following `next()`. It never allocates `Token` objects — `Token` is a debug/test snapshot used only by `tokenize()` and the dumper.
- Lexical context lives in the scanner: the indent stack that synthesizes `indent`/`dedent` tokens (and any newline-significance state) is scanner-owned. The parser never inspects whitespace or columns. Tea preserves Pine Script's line-structure rules, including grouped joining: inside an unclosed `(`, `[`, or `{` group, line breaks are insignificant and the indent machinery is bypassed. Declaration grammar may intentionally differ; Tea is not required to accept every Pine declaration form.
- Grammar facts preserved by the parser: `struct`/`type`/`interface`/`enum`/`import`/`export`/`to`/`by`/`in`/`as` are contextual keywords (declaration keywords only when the declaration shape follows; ordinary names elsewhere), while `this`, `emit`, and `return` are reserved; `this` produces `ThisExpr`; `method` and `inout` are ordinary identifiers with no declaration or parameter-mode grammar; simple statements chain with commas on one line; a bare `[a, b]` statement is a block's tuple value, not a declaration — `[a, b] = …` declares only when the balanced brackets land on `=`.
- `StructDecl.members` is the source-ordered owner of interleaved fields and nested methods. Methods always have an explicit result annotation and explicitly typed parameters; their implicit receiver is mutable unless `const` appears after the parameter list. Only `type Name = Type` produces `TypeAliasDecl`; block-form `type` and `struct` produce the same nominal declaration shape.
- `InterfaceDecl` owns method signatures only: its `InterfaceMethodDecl` nodes have explicit result/parameter annotations and receiver mode but no body field. Generic block-form `type`/`struct` declarations own constrained `TypeParam` nodes; constraints and type arguments remain ordinary recursive `TypeName` syntax.
- The parser owns its `Scanner` (`this.scanner`) and is the only caller of `next()`; lookahead is exactly the scanner's current token fields — no token buffering, no rescanning.
- `syntax.ts`'s `parse()` is the only frontend entry for modules outside this directory; `Scanner`/`Parser` are constructed nowhere else (`tokenize()` is the sanctioned debug exception).
- The syntax layer reports malformed-source errors through the injected `ErrorHandler` and continues with recovery; it never imports `Errors` — wiring reports into the compilation's error list is the noder/driver's job. `parse()` may return a partial `File` and never throws on malformed Tea source.
- All binary operators share the single `operator` token kind refined by `op`/`prec`; expression parsing is precedence climbing over `prec`, never per-operator token kinds.

- `emit <name-atom> <expression>` and `emit.append <name-atom> <expression>` produce one `EmitStmt`. A name atom is a quoted literal, a const-string binding, or a parenthesized constant expression; `append` is contextual only after `emit.`. The checker owns constant resolution, output identity, and cardinality. `ReturnStmt` exits a Tea function; a missing value is void. Ternary syntax remains `CondExpr` and later nodes as lazy `IfExpr`.
