# tea-lang

Clean-room Tea language toolchain — syntax (incremental scanner + parser) → typecheck → noder (`loadPackage` parses the package; `buildProgram` → Program) → codegen (lowering). `src/main.ts` is the executable shell, `src/cli/` owns commands, and `src/compiler.ts` is the pipeline driver. The `tea` CLI has four verbs: `run`, `build`, `parse`, `docs`.

## Invariants

- Never create new interfaces or abstractions without explicit approval.
- tea-lang is an independent clean-room repository: no imports or dependencies from sibling or host repositories anywhere in this repository, ever. When a definition from another repository is needed (e.g. a DataSeries shape), define the Tea-owned contract here instead of importing it across repositories.
- Import style is also an exception to the repo standard: cross-folder imports inside this package use relative paths (`../base/pos`), never a workspace package name, so the tree works unchanged outside the monorepo.
- External dependencies must be open-source-friendly npm packages only. Core runtime dependencies are pinned `commander` and `open`; the Node-hosted source CLI uses pinned `tsx`, and GPU execution uses optional `webgpu`. Mintlify is the hosted documentation tool; Docusaurus remains only as the offline package renderer, and both are build tooling alongside React and formatting/type packages. `package.json` must not use workspace-only version protocols (`catalog:`, `workspace:`) — concrete versions only, so `npm install` works on a standalone checkout.
- `examples/` is the human-facing runnable catalog. JavaScript embedding examples live under `examples/api/`, strategies under `examples/strategy/<name>/`, indicators under `examples/indicator/`, language demonstrations under `examples/language/`, and immutable inputs plus provenance under `examples/data/`; nothing under `src/` or `tests/fixtures/` may depend on it, and examples may hit the network (tests never do).
- Tests are either colocated `*.test.ts` files or cross-cutting suites under `tests/`; their shared fixtures live under `tests/fixtures/`. Nothing may read paths outside the repository tree, so `npm test` passes on a standalone checkout. `tests/fixtures/corpus/` is parse-only: original scripts plus fixtures derived from real-world Pine (comments and long strings stripped, statement groups dropped — derivations, never literal copies of third-party scripts). It must not be promoted into a checker/runtime promise.
- `tests/fixtures/execution/` owns compile-through and differential conformance. Its manifest is a fail-closed, hash-pinned inventory; every case runs through real compile, load, finite DataStream adaptation, `Node.bind()`, `Node.to()`, and the CLI trace formatter. Differential references must be independently hand- or specification-derived, tolerances must be explicit, and the exact deviation ledger records only consciously adopted Tea contracts — never skips unresolved findings. There is no automatic reference rewrite mode. See `docs/conformance.md`.
- The Tea Script frontend inside `packages/tsgraph` is a separate legacy surface; this package is its clean-room successor prototype and must not import from it.
- `src/main.ts` only invokes `runCli(process.argv)` and assigns its exit code.
  `src/cli/cli.ts` owns Commander, dispatch, logging, and the CLI error boundary;
  `src/cli/compiler-tools.ts` owns parse/build command handling.
- Type names describe the value's present role, never the imperative procedure that created it. Do not use `Resolved*` type names; name the resulting value directly (`NativeReceiver`, `GpuBinding`).
- Non-trivial public interfaces and the main methods of their concrete
  implementations carry explanatory TSDoc at the level of `src/api/node.ts`:
  document ownership, lifecycle or ordering semantics, and a concrete example
  where it clarifies use. Comments explain the contract and why it exists,
  rather than restating the signature.
- User-facing errors flow through a single per-compilation `Errors` instance (`src/base/print.ts`), owned by the driver (`compile.ts`) or the CLI. The syntax layer receives only a narrow injected `ErrorHandler` and continues with recovery; the noder is where reports enter the compilation's `Errors`. Reports queue with one-per-line suppression, are sorted and deduped at `flushErrors()`, and are printed only by `main.ts`. Phase barriers in `compile()` stop later phases after a failed one. User errors are never thrown; internal invariant violations use `fatal()`/`unimplemented()` (`InternalError`, never queued).
- Every position is a `Pos` carrying its `PosBase`, so file identity travels with positions and errors need no separate filename threading (`src/base/pos.ts`); lines and columns are 1-based. Every AST node carries the `Pos` of its leftmost defining token.
- `src/compiler.ts` owns one source-to-`Program` frontend
  (`compileToProgram`): load, import resolution, checking, and noding occur
  exactly once in that order. Every backend consumes that same `Program`;
  execution modes must not add a parallel compiler entry, wrapper IR, or
  strategy-only compilation path.
- `src/codegen/` owns bind-independent lowering from the one Program. The CPU target is ordinary TypeScript importing `tea/runtime`, with a program-specific Context, named state/inputs/outputs, lexical functions, and one ABI-13 Module tree. Builds and CI typecheck that source; synchronous template loading transpiles the same source. There is no separate JavaScript emitter, numeric function table, public manifest, or preparation method. Module owns binding configuration; Context owns execution state. Request records keep context/policy beside their child Module. WGSL consumes the same Program and the neutral physical contract in `src/gpu/contract.ts`; codegen never accepts datasets, devices, jobs or runtime buffers and never recognizes trade/broker/portfolio policy names.
- `src/runtime/` owns execution mechanics (`docs/runtime.md` is the authority, with request synchronization detailed in `docs/requests.md`). `src/runtime/js/` owns Context, captured Value, Input/Series, Heap, structs, and collections, while `src/runtime/gpu/` owns WebGPU sessions. Context owns mutable frame/input/request history and accepts synchronized values through `step()`; Module owns none of that state. Context commits state and buffered outputs after main returns successfully, aborts failed attempts, and preserves var/varip semantics. Public `Node` is the CPU execution owner: it owns the reactive graph, root and request-child runtimes, index progression, synchronization, Pine builtin delivery, and lossless `Datum` publication. Applications bind their own `DataStream`s; Tea has no parallel host-orchestration layer. GPU accepts concrete `GpuBinding` arrays and derives physical capacities only from the artifact, input extent, and actual device limits. `src/base/tabwriter.ts` owns CLI table alignment.
- `src/recipe/recipe.ts` owns the only shared Recipe contract: one configured Tea run exposes `execute(): Promise<R>`. A Recipe is a common way of wiring the public `Node` API; concrete Recipes bind public inputs with `Node.bind()`, attach public observers with `Node.to()`, and wait for that graph to finish. They never construct `Context`, bind compiled parameters, step request children, inspect layouts, or publish `Datum` values themselves. Finite indices, provisional attempts, commit, inputs, and disposal do not belong to the shared interface. `src/recipe/batch/index.ts` is the complete production Batch implementation and imports only the public API plus `Recipe`.
- `src/api/` owns JavaScript embedding and the synchronous mutable Node. Parameter binding is implemented only by `Module.bind(values, context?)`; Node delegates parameter patches to its stable module tree and owns all stream connections, clocks, synchronization and readiness. Failed binding leaves the tree unchanged; binding closes when execution starts. Modules never store Observables, supplied-stream flags or a parallel binding-result object. Request streams bind by direct declaration name, and each request record contains its child module. Tea checks each named column's type, mode, and plain-write uniqueness before projecting the sole Arrow output schema. Raw set values and append lists share declaration-ordered IDs; append columns are independent. Values are detached at emission, NaN is preserved, and failed steps publish nothing. Observer failure terminates the shared graph. Node remains final-only; the existing runtime provisional/var/varip/Heap semantics are unchanged. `docs/requests.md` owns scalar and collect synchronization policies.
- `src/cli/output.ts` owns terminal reports and machine traces. They are CLI
  details, not public reporting or sink abstractions.
- `docs/memory-model.md` owns source-observable assignment, mutation, history,
  collection, struct-reference, implicit-method-receiver, and persistence
  semantics. Block-form `struct Foo` and compatible `type Foo` declare the same
  nominal `StructType`; assignment and history carry its source-hidden
  `Ref<V>`, while its Heap-owned body remains live and transactionally
  mutable. Collections remain value-semantic headers over persistent backing.
  `const` receivers are shallow, and history syntax applies only to direct
  readable bindings. `docs/ir.md` owns only the static Program projection, and
  `docs/runtime.md` owns physical layout and commit/publication.
- `docs/strategy.md` owns ordinary program composition with concrete trade coordinators, deterministic reference lifecycles, and the boundary between Tea-owned broker/portfolio policy and host orchestration. Entry programs have no indicator/strategy header or runtime Strategy value.
- `docs/` owns the published Tea content and its Mintlify `docs.json`; hosted navigation is defined there. `website/` is only the Docusaurus renderer for the version-matched static build packaged with `tea docs`. Human-authored guide pages and compiler-generated reference pages are separate surfaces. Reference generation is an offline, deterministic projection of checker-owned public types and native functions; `tea docs` serves only the packaged static build on loopback and never runs Mintlify, Docusaurus, or AI at runtime.
- `src/checker/` implements the qualifier × value-type checker. Its semantic source of truth is `Package → Scope → Object → Type`; one `Info` per semantic context records only syntax-occurrence facts such as definitions, uses, types, selections, scopes, calls, and reassignment. The checker is wired into `compileToProgram()` between parse and noding behind a phase barrier. `src/loader/` owns source loading and import resolution (the driver injects its `Importer` into the checker — the checker never resolves paths); `src/noder/` consumes the checked package and facts without re-checking, and is the sole projection into Program-owned names, numeric series inputs, typed builtins, params, requests, slots, and frame layout. `src/ir/dumper.ts` renders Programs for `tea parse --ir` and the IR goldens.
- `src/tea-lib/` holds compiler-shipped Tea-authored libraries, each a real Tea library with a `library("...")` declaration and `export` functions compiled by the ordinary loader/checker/noder pipeline. `ta` is implicitly imported as a namespace; `visual` is a flattened function prelude whose ordinary `plot` constructs a library value, writes `emit id p`, and returns it. Trade components `broker`, `portfolio`, and `trade` require explicit imports so execution, accounting, and lifecycle policy remain visible in source. All entries use the same Program; `import trade` selects ordinary library policy. Policy-specific trade coordinators store their concrete broker and portfolio values directly; they must not become a universal wrapper whose unused methods or state enlarge reachable GPU closures. Nothing except calls to catalog intrinsics inside these libraries is native, and a parse error there is a compiler defect (`fatal`), never a user error.
- `src/testing/` holds cross-pass test DSLs and the execution-conformance schema/harness; pass-specific helpers stay in their pass directory (`syntax/testing.ts`, `checker/testing.ts`).
- `editors/vscode/` owns the activation-free VS Code/Cursor TextMate grammar for
  `.tea` files. It contains no execution host, dashboard, Webview, or compiler
  process protocol, and must never copy the legacy TSGraph Tea Script grammar.
