# tea-lang

Clean-room Tea language toolchain — syntax (incremental scanner + parser) → typecheck → noder (`loadPackage` parses the package; `buildProgram` → Program) → codegen (lowering). `src/main.ts` is the executable shell, `src/cli/` owns commands, and `src/compiler.ts` is the pipeline driver. The `tea` CLI has six verbs: `execute`, `run`, `sweep`, `build`, `parse`, `docs`.

## Invariants

- Never create new interfaces or abstractions without explicit approval.
- tea-lang is an independent clean-room repository: no imports or dependencies from sibling or host repositories anywhere in this repository, ever. When a definition from another repository is needed (e.g. a DataSeries shape), define the Tea-owned contract here instead of importing it across repositories.
- Import style is also an exception to the repo standard: cross-folder imports inside this package use relative paths (`../base/pos`), never a workspace package name, so the tree works unchanged outside the monorepo.
- External dependencies must be open-source-friendly npm packages only. Core runtime dependencies are pinned `commander`, `open`, and `yaml`; the Node-hosted source CLI uses pinned `tsx`, and GPU execution uses optional `webgpu`. Mintlify is the hosted documentation tool; Docusaurus remains only as the offline package renderer, and both are build tooling alongside React and formatting/type packages. `package.json` must not use workspace-only version protocols (`catalog:`, `workspace:`) — concrete versions only, so `npm install` works on a standalone checkout.
- `examples/` is the human-facing runnable catalog. JavaScript embedding examples live under `examples/api/`, strategies under `examples/strategy/<name>/`, indicators under `examples/indicator/`, language demonstrations under `examples/language/`, and immutable inputs plus provenance under `examples/data/`; nothing under `src/` or `tests/fixtures/` may depend on it, and examples may hit the network (tests never do).
- Tests are either colocated `*.test.ts` files or cross-cutting suites under `tests/`; their shared fixtures live under `tests/fixtures/`. Nothing may read paths outside the repository tree, so `npm test` passes on a standalone checkout. `tests/fixtures/corpus/` is parse-only: original scripts plus fixtures derived from real-world Pine (comments and long strings stripped, statement groups dropped — derivations, never literal copies of third-party scripts). It must not be promoted into a checker/runtime promise.
- `tests/fixtures/execution/` owns compile-through and differential conformance. Its manifest is a fail-closed, hash-pinned inventory; every case runs through the real compile, load, bind, `runAll`, and `TraceSink` path. Differential references must be independently hand- or specification-derived, tolerances must be explicit, and the exact deviation ledger records only consciously adopted Tea contracts — never skips unresolved findings. There is no automatic reference rewrite mode. See `docs/conformance.md`.
- The Tea Script frontend inside `packages/tsgraph` is a separate legacy surface; this package is its clean-room successor prototype and must not import from it.
- `src/main.ts` only invokes `runCli(process.argv)` and assigns its exit code.
  `src/cli/cli.ts` owns Commander, dispatch, logging, and the CLI error boundary;
  `src/cli/compiler-tools.ts` owns parse/build command handling.
- Type names describe the value's present role, never the imperative procedure that created it. Do not use `Resolved*` type names; name the resulting value directly (`ParameterGrid`, `ExecutionContext`, `NativeReceiver`, `ContextSeries`).
- User-facing errors flow through a single per-compilation `Errors` instance (`src/base/print.ts`), owned by the driver (`compile.ts`) or the CLI. The syntax layer receives only a narrow injected `ErrorHandler` and continues with recovery; the noder is where reports enter the compilation's `Errors`. Reports queue with one-per-line suppression, are sorted and deduped at `flushErrors()`, and are printed only by `main.ts`. Phase barriers in `compile()` stop later phases after a failed one. User errors are never thrown; internal invariant violations use `fatal()`/`unimplemented()` (`InternalError`, never queued).
- Every position is a `Pos` carrying its `PosBase`, so file identity travels with positions and errors need no separate filename threading (`src/base/pos.ts`); lines and columns are 1-based. Every AST node carries the `Pos` of its leftmost defining token.
- `src/compiler.ts` owns one source-to-`Program` frontend
  (`compileToProgram`): load, import resolution, checking, and noding occur
  exactly once in that order. Every backend consumes that same `Program`;
  execution modes must not add a parallel compiler entry, wrapper IR, or
  strategy-only compilation path.
- `src/codegen/` owns bind-independent target lowering. The JS backend emits one uniform recursive Runtime-ABI-7 `JSModule`: every root and request child carries the same ABI, shared `layout` table, manifest, and code shape. Static configuration emits directly in the manifest; generated `concretize(manifest, contextConstants?)` writes only late facts into a caller-owned fresh manifest copy, and only `main`/`funcs` consume the execution-only `RuntimeContext`. The WGSL backend audits its supported generic `Program` subset and emits a complete shader/layout artifact plus the ordinary generated JS module. `src/gpu/contract.ts` is the neutral, versioned physical artifact boundary shared by that producer and the GPU runtime consumer; neither side may duplicate its fixed bindings, descriptor offsets, or scalar strides. Codegen never accepts datasets, scenario jobs, devices, or runtime buffer payloads, and never recognizes `trade`, `broker`, `portfolio`, a coordinator type, or a lifecycle method by name.
- `src/runtime/` owns execution (`docs/runtime.md` is the authority, with request synchronization detailed in `docs/requests.md`). Shared ABI, binding, provider, value, and layout contracts remain at the runtime root; `src/runtime/js/` owns `JSRuntime`, fixed-history execution, State, Heap, structs, and collections, while `src/runtime/gpu/` owns WebGPU sessions. `JSRuntime` owns all mutable frame/input/request history and accepts synchronized values through `step()`; the module owns none of that state. `bindFixedHistory()` owns provider/sink I/O, row chronology, fixed-width accounting, and recursive scalar request execution. Public Node separately materializes `security_lower_tf` batches as parent-Heap arrays. GPU preparation applies each binding to a copied manifest through shared `runtime/module-binding.ts`, never through a CPU runtime instance. `src/providers/` holds host adapters, and `src/base/tabwriter.ts` owns CLI table alignment.
- `src/api/` owns the JavaScript embedding surface. `bindModule(module, assignments)` is an immutable, subscription-free `Effect<JSModule, BindingError>` whose only binding forms are host-neutral parameter values and series-supplied markers. It deep-copies the recursive manifest tree, applies the assignment and direct generated concretization, freezes the result, and returns a new module snapshot while old references remain unchanged. It never stores an Observable, DataStream, provider, compiler `Program`, or parallel binding-result object in the module. Public `Node` is a synchronous mutable interface; file-private `TeaNode` directly owns one module context, its RxJS data, and request-child Nodes. Request streams bind by the direct top-level request declaration's variable name, never by symbol; every key is validated before mutation, and a root-series/request-name collision is ambiguous. `.to()` recursively runs child Nodes, folds request results into the parent through `sync()` in dense request-id order, converts internal `StepResult` once through `toDatum()`, publishes only the output Datum, returns a sink subscription after setup, and lets RxJS teardown interrupt in-flight step Effects. `security` is scalar one-to-one; `security_lower_tf` selects count-window, event-time-window, then one-to-one-array synchronization in that order. Binding is rejected after execution starts or disposal. `JSModule.ready()` and `remaining()` derive binding state from the concrete manifest. Builtin row wiring remains unsupported. `docs/requests.md` is the detailed Node synchronization authority.
- `src/reporting/` owns structured run and sweep report values, including the
  bounded trajectories captured by the original execution. It never owns an
  editor session, dashboard, renderer, or selected-binding replay.
- `docs/memory-model.md` owns source-observable assignment, mutation, history,
  collection, struct-reference, implicit-method-receiver, and persistence
  semantics. Block-form `struct Foo` and compatible `type Foo` declare the same
  nominal `StructType`; assignment and history carry its source-hidden
  `Ref<V>`, while its Heap-owned body remains live and transactionally
  mutable. Collections remain value-semantic headers over persistent backing.
  `const` receivers are shallow, and history syntax applies only to direct
  readable bindings. `docs/ir.md` owns only the static Program projection, and
  `docs/runtime.md` owns physical layout and commit/publication.
- `docs/strategy.md` owns the native strategy declaration, the rule that the entry source plus its policy state is the strategy, the direct policy-specific trade coordinators, deterministic reference lifecycles, and the boundary between Tea-owned broker/portfolio semantics and physical host orchestration. There is no universal runtime Strategy value or host lifecycle hook.
- `docs/` owns the published Tea content and its Mintlify `docs.json`; hosted navigation is defined there. `website/` is only the Docusaurus renderer for the version-matched static build packaged with `tea docs`. Human-authored guide pages and compiler-generated reference pages are separate surfaces. Reference generation is an offline, deterministic projection of checker-owned public types and native functions; `tea docs` serves only the packaged static build on loopback and never runs Mintlify, Docusaurus, or AI at runtime.
- `src/checker/` implements the qualifier × value-type checker. Its semantic source of truth is `Package → Scope → Object → Type`; one `Info` per semantic context records only syntax-occurrence facts such as definitions, uses, types, selections, scopes, calls, and reassignment. The checker is wired into `compileToProgram()` between parse and noding behind a phase barrier. `src/loader/` owns source loading and import resolution (the driver injects its `Importer` into the checker — the checker never resolves paths); `src/noder/` consumes the checked package and facts without re-checking, and is the sole projection into Program-owned names, numeric series inputs, typed builtins, params, requests, slots, and frame layout. `src/ir/dumper.ts` renders Programs for `tea parse --ir` and the IR goldens.
- `src/tea-lib/` holds compiler-shipped Tea-authored libraries, each a real Tea library with a `library("...")` declaration and `export` functions compiled by the ordinary loader/checker/noder pipeline. `ta` is implicitly imported as a namespace; `visual` is a flattened prelude whose unqualified `plot` wrapper calls the native `output()` declaration intrinsic. Trade components `broker`, `portfolio`, and `trade` require explicit imports so execution, accounting, and lifecycle policy remain visible in source. The native `strategy()` declaration is unrelated to `import trade`. Policy-specific trade coordinators store their concrete broker and portfolio values directly; they must not become a universal wrapper whose unused methods or state enlarge reachable GPU closures. Nothing except calls to catalog intrinsics inside these libraries is native, and a parse error there is a compiler defect (`fatal`), never a user error.
- `src/testing/` holds cross-pass test DSLs and the execution-conformance schema/harness; pass-specific helpers stay in their pass directory (`syntax/testing.ts`, `checker/testing.ts`).
- `editors/vscode/` owns the activation-free VS Code/Cursor TextMate grammar for
  `.tea` files. It contains no execution host, dashboard, Webview, or compiler
  process protocol, and must never copy the legacy TSGraph Tea Script grammar.
