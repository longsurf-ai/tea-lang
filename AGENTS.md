# tea-lang

Clean-room Tea language toolchain — syntax (incremental scanner + parser) → typecheck → noder (`loadPackage` parses the package; `buildProgram` → Program) → codegen (lowering). `src/main.ts` is the CLI shell; `src/compile.ts` is the pipeline driver. The `tea` CLI has five verbs: `run`, `sweep`, `build`, `parse`, `docs`.

## Invariants

- tea-lang is an independent clean-room repository: no `@openchart/*` imports or dependencies anywhere in this repository, ever. When a definition from OpenChart is needed (e.g. a DataSeries shape), define the Tea-owned contract here instead of importing it across repositories.
- Import style is also an exception to the repo standard: cross-folder imports inside this package use relative paths (`../base/pos`), never a workspace package name, so the tree works unchanged outside the monorepo.
- External dependencies must be open-source-friendly npm packages only. Core runtime dependencies are `commander` and `open`; the GPU CLI host uses optional `webgpu` and `tsx`. Docusaurus, React, and formatting/type packages are documentation build tooling. `package.json` must not use workspace-only version protocols (`catalog:`, `workspace:`) — concrete versions only, so `npm install` works on a standalone checkout.
- `examples/` holds runnable demo scripts + fixtures for humans (`requests-tour.tea` over `primary.csv`); nothing under `src/` or `testdata/` may depend on it, and examples may hit the network (tests never do).
- Tests and fixtures are fully in-repository (colocated `*.test.ts` plus `testdata/`, Go style): nothing may read paths outside the repository tree, so `bun test` passes on a standalone checkout. `testdata/corpus/` is parse-only: original scripts plus fixtures derived from real-world Pine (comments and long strings stripped, statement groups dropped — derivations, never literal copies of third-party scripts). It must not be promoted into a checker/runtime promise.
- `testdata/execution/` owns compile-through and differential conformance. Its manifest is a fail-closed, hash-pinned inventory; every case runs through the real compile, load, bind, `runAll`, and `TraceSink` path. Differential references must be independently hand- or specification-derived, tolerances must be explicit, and the exact deviation ledger records only consciously adopted Tea contracts — never skips unresolved findings. There is no automatic reference rewrite mode. See `docs/conformance.md`.
- The Tea Script frontend inside `packages/tsgraph` is a separate legacy surface; this package is its clean-room successor prototype and must not import from it.
- `src/main.ts` is Commander wiring and process I/O only. Pipeline stage order is owned solely by `src/compile.ts`; no other module may chain stages.
- User-facing errors flow through a single per-compilation `Errors` instance (`src/base/print.ts`), owned by the driver (`compile.ts`) or the CLI. The syntax layer receives only a narrow injected `ErrorHandler` and continues with recovery; the noder is where reports enter the compilation's `Errors`. Reports queue with one-per-line suppression, are sorted and deduped at `flushErrors()`, and are printed only by `main.ts`. Phase barriers in `compile()` stop later phases after a failed one. User errors are never thrown; internal invariant violations use `fatal()`/`unimplemented()` (`InternalError`, never queued).
- Every position is a `Pos` carrying its `PosBase`, so file identity travels with positions and errors need no separate filename threading (`src/base/pos.ts`); lines and columns are 1-based. Every AST node carries the `Pos` of its leftmost defining token.
- `src/compile.ts` owns one source-to-`Program` frontend (`compileToProgram`): load, import resolution, checking, and noding occur exactly once in that order. Every backend consumes that same `Program`; execution modes must not add a parallel compiler entry, wrapper IR, or strategy-only compilation path.
- `src/codegen/` owns bind-independent target lowering. The JS backend emits self-describing modules against the Runtime ABI; the WGSL backend audits its supported generic `Program` subset and emits a complete module plus target layouts. Codegen never accepts datasets, scenario jobs, devices, or runtime buffer payloads, and never recognizes strategy libraries by package name.
- `src/runtime/` owns execution (`docs/runtime.md` is the authority). `JSRuntime` owns frames, rings, the provisional/commit protocol, and the injected DataProvider/OutputSink seams; generic CPU batching repeatedly binds one compiled JS module to isolated jobs and captures outputs through an OutputSink. The GPU runtime creates one resumable session from a compiled WGSL artifact, an injected device, and the same ordered `BindInputs[]`: it resolves providers, packs bounded buffers, preserves each Program execution's state across chunks, and publishes decoded dense/effect rows through caller sinks. `src/providers/` holds host-side seam adapters — `providers/data/` (DataProviders; `csv.ts` today), `providers/gpu/` (optional device/process hosts), and `providers/sinks/` (`RunReportSink`/`SweepReportSink` for human reports, `TraceSink` for `--trace` / run goldens — TraceSink alone owns the machine trace format). `src/base/tabwriter.ts` owns column alignment for CLI tables; printers write cells, never invent padding. `runtime.ts` at the package root is superseded design notes.
- `docs/memory-model.md` owns source-observable value copying, aggregate mutation, history, collection, user-type, implicit-method-receiver, and future pointer semantics. Block-form `struct Foo` and `type Foo` declare the same nominal value type; nested methods use a non-escaping implicit `this`, while ordinary values and history never gain pointer identity. Collection values are immutable headers over immutable backing. Physical placement and sharing must never introduce source-visible identity. `docs/ir.md` owns only the static Program projection, and `docs/runtime.md` owns physical layout and publication.
- `docs/strategy.md` owns the strategy declaration, explicit Tea component-state model, deterministic reference lifecycle, and the boundary between Tea-owned broker/portfolio semantics and physical host orchestration.
- `docs/` owns the published Tea content and `website/` owns its Docusaurus reader shell. Human-authored guide pages and compiler-generated reference pages are separate surfaces. Reference generation is an offline, deterministic projection of checker-owned public types and native functions; `tea docs` serves only the packaged static build on loopback and never runs Docusaurus or AI at runtime.
- `src/checker/` implements the qualifier × value-type checker. Its semantic source of truth is `Package → Scope → Object → Type`; one `Info` per semantic context records only syntax-occurrence facts such as definitions, uses, types, selections, scopes, calls, and reassignment. The checker is wired into `compileToProgram()` between parse and noding behind a phase barrier. `src/loader/` owns source loading and import resolution (the driver injects its `Importer` into the checker — the checker never resolves paths); `src/noder/` consumes the checked package and facts without re-checking, and is the sole projection into Program-owned names, numeric series inputs, typed execution inputs, params, requests, slots, and frame layout. `src/ir/dumper.ts` renders Programs for `tea parse --ir` and the IR goldens.
- `src/lib/` holds compiler-shipped Tea-authored libraries, each a real Tea library with a `library("...")` declaration and `export` functions compiled by the ordinary loader/checker/noder pipeline. `ta` is implicitly imported; strategy components `broker`, `portfolio`, and `strategy` require explicit imports so execution, accounting, and lifecycle policy remain visible in source. Nothing in these libraries is native, and a parse error there is a compiler defect (`fatal`), never a user error.
- `src/testing/` holds cross-pass test DSLs and the execution-conformance schema/harness; pass-specific helpers stay in their pass directory (`syntax/testing.ts`, `checker/testing.ts`).
- `editors/vscode/` owns the activation-free VS Code/Cursor editor projection for `.tea` files. Its TextMate grammar is generated from the current scanner/checker vocabulary; it must never copy or merge the legacy TSGraph Tea Script grammar.
